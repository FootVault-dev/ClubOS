- [ ] **T12. `/t.js` embeddable tracker.** Public route serving a tiny JS tracker for the marketing sites (each site loads it from ITS same-root ClubOS domain, e.g. minifootball.co.nz ← join.minifootball.co.nz): boots visitor via a `POST /api/public/analytics/hello` (server Set-Cookie usg_vid — first-party per brand root), sends page_view/utm/fbclid/ci touches to the collector, and decorates outbound links pointing at our OTHER funnel domains with `?vi=<visitor>&ci=<click>` (domain list served with the script). - [ ] **T13. Cross-root acceptance.** Cookie middleware (T4) extended: incoming `?vi=` on a landing → if no existing `usg_vid`, adopt it (server Set-Cookie); if one exists and differs, record an `alias` event linking both visitor ids (analytics_events metadata) so identity stitching can bridge; `?ci=` already handled. Tests for the adopt/alias decision matrix in `script/test-attribution-spine.ts`.
- [ ] **T14. Mailer instrumentation.** In MFL + CIC broadcast senders and the main transactional templates (`server/email.ts` + broadcast routes): rewrite hrefs pointing at our domains to append utm_source=email, utm_medium=broadcast|transactional, utm_campaign=<campaign slug/id>, and for broadcasts a per-recipient signed `ci` token (HMAC pattern like mflUnsubToken; token resolvable server-side to the recipient email → identity bind on click via T13 middleware + a small resolver).
